The event runs over two days, with deployment work before day one. [The customer story](../customer-story/) explains who you are working for and why. A team works through the day's challenges in parallel where a challenge is scoped to a member, and together where it's scoped to the team.

## Before the event

Before day one, your team sets up the repositories, the shared landing zone, and each member's simulated datacenter in four numbered steps. **No coach is available during the pre-hackathon**, and pre-hackathon support is best-effort. Your **designated team lead** is your first point of contact.

The dates count back from day one, and the steps in [Deploy](../../deploy/) follow the exact chronological order below:

1. **[Step 1: Repo and preflight (T-14)](../../deploy/set-up-your-repo/) (Everyone + Team lead):** meet the [requirements](../requirements/), create your private repo from `apex-accelerator`, import the kit into `factory/`, sign in, and create `.local/settings.json`. Members send their four roster values privately to the team lead and set up the member pipeline; the team lead builds `.local/roster.json` and sets up the lead pipeline. Everyone runs the `whatif` preflight and completes the manual checks.
2. **[Step 2: Foundation and Graph grant (T-7)](../../deploy/team-lead-steps/) (Team lead + Privileged Role Administrator):** the team lead runs the `foundation` stage to deploy ALZ-lite in the shared services subscription. A Privileged Role Administrator then runs `Grant-SqlMiDirectoryRead.ps1` once for the team. Members have nothing to run at T-7.
3. **[Step 3: Datacenter and workstation (T-3)](../../deploy/member-steps/) (Everyone):** every member (including the team lead) runs the `member` stage to deploy their datacenter, run `Test-Datacenter.ps1` while both VMs are running, and onboard `vm-app01` to Azure Arc. The test runs before Arc because Arc turns off VM run commands. You then run the first Arc SQL migration assessment in the portal, set up `vm-dev01` with VS Code and GitHub Copilot, and commit `factory/evidence/readiness/`.
4. **[Step 4: Vending (T-1)](../../deploy/vending/) (Team lead + Everyone):** every member makes sure both datacenter VMs are running. The team lead runs the `vending` stage, which automatically checks that each member's datacenter VNet and Arc-connected `vm-app01` are ready, vends each spoke into the foundation, restarts the VMs, records the datacenter policy exemptions, and runs the connectivity probes.

T-14 and T-3 are the readiness milestones for members. At T-1, vending stops at the first member whose datacenter or Arc connection is not ready: earlier members are vended but not restarted, exempted or probed, and later members are not vended. Fix the cause and re-run vending for all members; it is safe to repeat. If phase 2 fails while restarting VMs, fix the cause and re-run for all members. If phase 3 names members whose exemptions or connectivity probes failed, re-run for those named indexes only. Raise blockers with your team lead early. The readiness check is a prerequisite, not a scored challenge.

## Day one

Day one opens at 08:30 with a **30-minute presentation by the tech lead** introducing the hackathon, the Contoso University scenario, the target architecture, and the 10 challenges.

At 09:00, everyone starts [C1: Define the opportunity](../../challenges/c01-define-the-opportunity/), the team lead included. C1 needs no Azure access. Next, in [C2: Secure, AI-ready foundation](../../challenges/c02-secure-ai-ready-foundation/), each member tests an AI coding agent against two layers of guardrails: APEX's repository security baseline and the Azure Landing Zone `Deny` policies in `rg-spoke`.

Members then assess the legacy application and database in [C3: Assess the source](../../challenges/c03-assess-the-source/), shape the target architecture as a team in [C4: Choose target states](../../challenges/c04-choose-target-states/), watch a coach's live APEX demo, and deploy the application platform in [C5: Deploy the CoE archetype with APEX](../../challenges/c05-deploy-the-coe-archetype/). [C6: Modernize with GHCP](../../challenges/c06-modernize-with-ghcp/) starts on day one and finishes on day two. The [agenda](../../about/#agenda) on the About page has the times.

## Day two

The MI link (the replication link from the source SQL Server to Azure SQL Managed Instance) starts at 08:30, in tasks 1 and 2 of [C7: Migrate and go live](../../challenges/c07-migrate-and-go-live/). That way seeding overlaps the end of C6. C6 finishes, then C7, [C8: Validate the pattern](../../challenges/c08-validate-the-pattern/), [C9: Optimize the DB with GHCP](../../challenges/c09-optimize-the-db-with-ghcp/) and [C10: Package, hand over, review AI readiness](../../challenges/c10-package-hand-over-review-ai-readiness/) close out the event with a team showcase.

## Time boxes are pacing, not hard stops

Each challenge page states a time box to help you pace the day. The real gates are T-14 and T-3 before the event and the end of each day during it, not each challenge's individual minutes.
