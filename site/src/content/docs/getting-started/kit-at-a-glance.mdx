## Where do I run this?

| Where | What you do there |
|---|---|
| Dev container | VS Code on your laptop, in your own repo. You trigger deployments with GitHub Actions and run the readiness setup, C1, C2, C4, C5 with APEX and `azd`, and C10 here. C8 uses both the dev container and `vm-dev01`. [Set up your repo](../../deploy/set-up-your-repo/) creates it. |
| [`vm-dev01`](../../guides/ghcp-upgrade/#switching-to-vm-dev01) | Your workstation, through Bastion. From C3 the app work happens here, next to the private network. During the event, never stop it. |
| Browser and Azure portal | The Azure Arc assessment (first run in the readiness check, triaged in C3), the MI link (C7), Bastion connections and the C8 smoke checks. |
| [Your own repo](../../challenges/c01-define-the-opportunity/#where-your-evidence-goes) | Evidence goes in `factory/evidence/` on `main`; run `git pull` first. On `vm-dev01`, use your plain clone `C:\src\<your-repo>` and run `git pull --rebase` first. Your coach reads it. |

Each challenge page has a **Where to run** block that says which one to use.

Your team lead assigns a distinct member index to each person. Teams use `1` to `5`, with the team lead as `1`; the scripts accept indexes from `1` to `20`.

## What changes

| Layer | From | To |
|---|---|---|
| App | .NET Framework 4.8 | .NET 10 and ASP.NET Core MVC |
| Hosting | IIS on `vm-app01` | A container image on App Service for Linux |
| Database | SQL Server | Azure SQL Managed Instance |
| Messaging | MSMQ | Azure Service Bus |

## The journey

Ten challenges across two days, from a defined opportunity to a reusable, AI-ready modernization pattern. Before day one, four numbered steps in [Deploy](../../deploy/) set up your repo, foundation, datacenter, and spoke vending.

<JourneyMap />

GHCP is GitHub Copilot. The MI link is the replication link from the source SQL Server to Azure SQL Managed Instance. The CoE archetype is a Center of Excellence's reference platform, built with APEX and deployed with `azd`.

## The end state

The team shares one hub. Each member has a datacenter, a spoke and a CoE archetype. The foundation and spoke vending are deployed in Steps 2 and 4 before the event, C2 tests the repository and landing-zone guardrails against an AI coding agent, C5 deploys the archetype, C7 links the database and C8 checks the result.
