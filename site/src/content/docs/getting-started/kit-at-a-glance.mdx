## Where do I run this?

| Where | What you do there |
|---|---|
| `vm-dev01` | Your single workstation through Bastion, next to the private network. You run 100% of `C1` to `C10` here in a single clone (`C:\src\<your-repo>` on `main`), including APEX and `azd` in C5 and the Upgrade agent in C3 and C6. Never stop it during the event. [Set up `vm-dev01`](../../deploy/member-steps/#33-set-up-vm-dev01) (Path A) or [Student onboarding](/deploy/lead-setup/student-onboarding/) (Path B). |
| Azure Cloud Shell | Browser shell (`https://shell.azure.com`) used before `vm-dev01` exists at T-3 to import the kit and dispatch `platform.yml` in Path A (or by the team lead in Path B), and at T+2 to run `teardown`. |
| Browser and Azure portal | The Arc assessment, MI link, Bastion and C8 live checks. Follow [the readiness assessment](../../deploy/member-steps/#32-run-the-first-arc-sql-assessment-and-check-hybrid-benefit) and [C7 migration](../../challenges/c07-migrate-and-go-live/). |
| Your own repo (`C:\src\<your-repo>` on `main`) | [Working artifacts](../../challenges/c01-define-the-opportunity/#where-your-evidence-goes) live in `factory/evidence/` on `main`, alongside `app/ContosoUniversity` and `infra/bicep/university` in the same repo. |

Each challenge page has a **Where to run** block that says which one to use.

Your team lead assigns a distinct positive whole-number member index to each person, starting at `1` with the team lead as `1`.

## What changes

| Layer | From | To |
|---|---|---|
| App | .NET Framework 4.8 | .NET 10 and ASP.NET Core MVC |
| Hosting | IIS on `vm-app01` | A container image on App Service for Linux |
| Database | SQL Server | Azure SQL Managed Instance |
| Messaging | MSMQ | Azure Service Bus |
| Uploads | Local filesystem | Azure Blob Storage |
| Secrets | Configuration files | Azure Key Vault and managed identity |
| Telemetry | Local trace output | Application Insights through OpenTelemetry |

## The journey

Ten challenges across two days, from a defined opportunity to a reusable, AI-ready modernization pattern. Before day one, four numbered steps in [Deploy](../../deploy/) set up your repo, foundation, datacenter, and spoke vending.

<JourneyMap />

GHCP is GitHub Copilot. The MI link is the replication link from the source SQL Server to Azure SQL Managed Instance. The CoE archetype is a Center of Excellence's reference platform, built with APEX and deployed with `azd`.

## The end state

The team shares one hub. Each member has a datacenter, a spoke and a CoE archetype. The foundation and spoke vending are deployed in Steps 2 and 4 before the event, C2 tests the repository and landing-zone guardrails against an AI coding agent, C5 deploys the archetype, C7 links the database and C8 checks the result.
