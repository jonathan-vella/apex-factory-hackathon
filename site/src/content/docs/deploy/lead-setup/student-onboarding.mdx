**Who:** **Every student** in a lead-provisioned event.
**When:** On Day 1 before starting [C1: Define the opportunity](/challenges/c01-define-the-opportunity/). Allow **20 to 30 minutes** once your team lead shares your private Handoff Card and lab sign-in details.

Your team lead has already deployed the shared Azure landing zone, your simulated datacenter (`vm-app01` and `vm-dev01`), Azure Arc, and your spoke network. Connect to `vm-dev01` through Azure Bastion on Day 1 and follow the steps below to get your private repository and Copilot tools ready before starting C1. Use the same clone (`C:\src\<your-repo>` on `main`) for all ten challenges.

If anything blocks you, ask your **team lead** or **coach**.

## 1. Accept your repository invitation

If you have not already accepted the GitHub invitation sent before Day 1, open the invitation link in your private Handoff Card and accept it with the GitHub account you gave your team lead. Confirm you can access the assigned private repository. Keep the card private: it contains your repository URL, archetype suffix, and local settings command. Do not create a new repository.

## 2. Connect to `vm-dev01` through Bastion and set up your workspace

Use the assigned repository owner, repository name, and archetype suffix from your Handoff Card in the bootstrap command below. The script signs you in, clones that existing repository, imports the kit, and writes local settings. It detects the shared hub subscription from the peering created by vending. The card's `Initialize-Settings.ps1` command is a manual alternative for initializing settings after cloning, not the bootstrap command.

### Check your setup on `vm-dev01`

Run in **PowerShell 7 (`pwsh`)** on `vm-dev01`:

```powershell
gh auth status
git config --global user.name
az account show --query name -o tsv
[Environment]::GetEnvironmentVariable('AZURE_TOKEN_CREDENTIALS', 'User')
git -C C:\src\<your-repo> branch --show-current
git -C C:\src\<your-repo> status --short --ignored -- app .github/upgrades
Get-Content C:\src\<your-repo>\factory\.local\settings.json
```

Done when GitHub is signed in, git has your name, Azure shows your workload subscription, `AZURE_TOKEN_CREDENTIALS` is `AzureCliCredential`, `C:\src\<your-repo>` is on `main`, `settings.json` has your `suffix`, `memberIndex`, and `sharedSubscriptionId`, and the `git status` command prints nothing. If the shared subscription was not detected, contact your team lead; the private Handoff Card also provides a local settings command. Keep `vm-dev01` running during the event—never shut down or deallocate it while hacking.

## 3. Confirm readiness on `main`

Your team lead already pushed `factory/evidence/readiness/test-datacenter.txt` to your student repository in Step 3:

1. In `C:\src\<your-repo>` on `vm-dev01`, confirm `factory/evidence/readiness/test-datacenter.txt` is present with `PASS` results.
2. In the Azure portal, open **Azure Arc** > **SQL Server instances**, select the instance on `vm-app01`, open **Migration** > **Assessments** (choose **Run assessment** if not yet run), and confirm the **Azure SQL Managed Instance** readiness report is available for C3.

Done when `factory/evidence/readiness/test-datacenter.txt` is present on `main` and VS Code + Copilot Chat are ready on `vm-dev01`. Let your team lead know you are ready!
