## Before you start

You need a second subscription (shared services) plus Owner at Tenant Root, the top management group of your tenant. A Global Administrator has to [elevate access](https://learn.microsoft.com/azure/role-based-access-control/elevate-access-global-admin) for that, so ask early: you deploy the foundation at T-7. You also still need your own workload subscription.

<Steps>

1. **Collect the roster.** Each colleague sends you four values privately, never in a repo or issue: workload subscription ID, member index, Entra object ID and work email (see [Member steps](../member-steps/#send-your-roster-values-to-your-team-lead)). A team is at most 5 people including you.

2. **Assign member indexes.** Each member needs a distinct number from 1 to 20. Use 1 to 5, and take 1 yourself. Tell each colleague theirs, because they need it for their settings file.

3. **Build the roster file.** One row per member, you included. Save it as `factory/.local/roster.json`, which stays out of git.

   ```json
   [
     { "index": 1, "subscriptionId": "<workload-subscription-id>", "memberPrincipalId": "<entra-object-id>", "budgetEmail": "<email>" }
   ]
   ```

4. **Set up the pipeline, once.** Use the lead profile with the roster. To add or change a member later, edit the file and run this again.

   ```powershell
   ./scripts/Initialize-PlatformPipeline.ps1 -RosterPath .local/roster.json
   ```

</Steps>

Done when the script reports its checks as passed. A repo has exactly one profile: don't run the member setup in the lead's repo.

## T-7 foundation

The `whatif` stage runs the preflight for every member in the roster, so a missing role or quota shows up now. The foundation takes 15 to 25 minutes.

```bash
gh workflow run platform.yml -f stage=whatif
gh workflow run platform.yml -f stage=foundation
```

Open the **Actions** tab and approve each run if GitHub asks. Done when both runs are green.

## Graph grant

A Privileged Role Administrator runs `Grant-SqlMiDirectoryRead.ps1` once for the team. No pipeline does this, and it must happen after the foundation and before C7. Send them the details below.

<details>
<summary>What to send the Privileged Role Administrator</summary>

They don't need your repo. They download the single file `https://raw.githubusercontent.com/jonathan-vella/apex-factory-hackathon/main/scripts/Grant-SqlMiDirectoryRead.ps1`, which has no other kit dependencies. They need PowerShell 7, the Azure CLI and Reader on the shared services subscription, and they run it from their own computer, signed in as themselves.

If it stops with `InteractionRequired` or `TokenCreatedWithOutdatedPolicies`, their sign-in is stale: they run `az logout` and `az login` again, then repeat. See the [ALZ-lite guide](../../guides/alz-lite/) and [C2](../../challenges/c02-secure-ai-ready-foundation/).

</details>

Done when the administrator confirms the script finished.

## T-3 your own datacenter

Do the member steps for your own datacenter. Use your own member index, the one you assigned yourself:

```bash
gh workflow run platform.yml -f stage=member -f members=<your-member-index>
```

## T-1 vending

Vending connects each member's subscription to the hub, restarts every VM, records policy exemptions and runs the connectivity probes. Wait until every member's datacenter exists and a coach has approved every readiness record, yours included. One approval of the run covers the whole stage.

```bash
gh workflow run platform.yml -f stage=vending
```

Plan on about an hour for three members and about 75 minutes for five. Done when the run is green.

If one member fails, fix the cause and run the stage for that member only. A member who is already connected is quick on a re-run.

```bash
gh workflow run platform.yml -f stage=vending -f members=<n>
```

<details>
<summary>Why it works this way</summary>

- The pipeline reads its members only from the roster, which setup stores as an environment secret. It never discovers members in Azure, and the guard accepts only those subscriptions.
- Members are connected one after another, because each run updates the shared firewall policy (4 to 5 minutes each). Then every VM restarts at once (about 25 minutes, the SQL VM is the slow one), and the policy scan and connectivity probes run in parallel.
- If a member redeploys their datacenter after vending, run vending for that member again.

</details>

## Save the foundation evidence

C2 asks for evidence of the foundation. Copy the run summaries of the `foundation` and `vending` stages into your `factory/evidence/` as C2 describes. The pipeline already redacts IDs: they show as `<id:abcd>`.

## If something breaks

Read the run's log, fix the cause and run the stage again: the stages are safe to repeat. After two attempts, ask your coach. [Troubleshooting](../../reference/troubleshooting/) lists the common errors.
