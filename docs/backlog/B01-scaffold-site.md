## Outcome

- The repo has the same docs tooling as the [APEX microhack](https://github.com/jonathan-vella/apex-microhack): markdownlint, Prettier, ESLint, Vale, lefthook, content-invariant and link checks, and Node tests. `npm run check` runs them.
- A Starlight site with six sections (Getting Started, Challenges, Modules, Guides, Reference, About) builds, passes CI and deploys to <https://factory.apexops.pro> through GitHub Pages.
- `versions.md` and `NOTICE` exist at the root.

The site pages are placeholders. B11 writes the content.

## Before you start

1. `node --version` prints `v24.` followed by any minor version.
2. `gh api repos/jonathan-vella/apex-factory-hackathon/pages` fails with `Not Found (HTTP 404)`, because Pages isn't set up yet. If it succeeds, skip enabling Pages in requirement 18.
3. `gh api repos/jonathan-vella/apex-microhack/commits/f95c470ed23016e0267097489174a050471f379c --jq .sha` prints that SHA.

## Notes and traps

- **Why so little is copied:** attendees open their copy of this repo in VS Code on the dev VM to modernize the app. Skills in `.github/skills/`, agent instructions and workspace settings load into those GitHub Copilot sessions and would change the results. B10 adds the modernization skills on purpose.
- `npm ci` installs the lefthook git hooks through the repo's `prepare` script. npm may warn that lefthook's `postinstall` isn't covered by `allowScripts`; ignore it.
- The 404 page and footer come from the microhack unchanged. That's fine.
- GitHub ignores `site/public/CNAME` when Pages builds with Actions. The domain comes from the Pages API. The file stays to match the reference.
- The microhack CI ran markdownlint only on site content. `npm run check` lints every Markdown file in the repo, including `docs/`, so the backlog must pass markdownlint too.
- If `npm run format:check` fails, run `npm run format`, then run the checks again.
