# Issue #198: Microsoft Learn reference findings

**Checked:** 2026-10-31

**Scope:** Current Microsoft Learn guidance and the merged documentation changes in [PR #210](https://github.com/jonathan-vella/apex-factory-hackathon/pull/210). This is a documentation review, not a current-version runtime retest or a new Azure portal verification.

## Findings

| Topic | Current evidence | Repository status |
| --- | --- | --- |
| Upgrade dashboard in VS Code | [The overview](https://learn.microsoft.com/dotnet/core/porting/github-copilot-upgrade/overview) says the dashboard is not currently available inside Visual Studio, VS Code, or other IDEs. [The dashboard page](https://learn.microsoft.com/dotnet/core/porting/github-copilot-upgrade/dashboard) also describes browser access from an IDE. These pages do not establish an embedded VS Code dashboard or consistent dashboard availability in every IDE session. | **Updated:** C3 describes the dashboard as optional, cites Learn's presentation guidance, and retains direct assessment and plan file review when it is unavailable (`site/src/content/docs/challenges/c03-assess-the-source.md`). |
| Starting the agent | [Install guidance](https://learn.microsoft.com/dotnet/core/porting/github-copilot-upgrade/install) says VS Code users can send `@upgrade`; the extension also adds an `Upgrade` agent-picker entry. These are both supported ways to start it. | C6 accepts either the picker or `@upgrade`; this is accurate. The picker should not be described as the only VS Code entry point. |
| Dashboard tabs | The current [dashboard reference](https://learn.microsoft.com/dotnet/core/porting/github-copilot-upgrade/dashboard) lists **Tasks**, not an **Execution** tab. It does not establish that the old **Start** action is available on that tab. | **Updated:** both the C6 “Run a task” prompt (`site/src/content/docs/prompts/vscode/02-run-a-task.md`) and `.github/modernization/playbook.md` now use their existing `start_task` prompt without an unverified dashboard-button instruction. |
| .NET Upgrade Assistant | The [Upgrade Assistant overview](https://learn.microsoft.com/dotnet/core/porting/upgrade-assistant-overview) marks .NET Upgrade Assistant as “officially deprecated” and directs users to the GitHub Copilot modernization chat agent. | PR #210 replaced the old Upgrade Assistant learning-path reference with GitHub Copilot upgrade content. The two Copilot agents are distinct: .NET upgrades use GitHub Copilot upgrade; Azure migrations use GitHub Copilot modernization. |
| Application Insights Search | [Current Application Insights guidance](https://learn.microsoft.com/azure/azure-monitor/app/failures-performance-transactions) names the **Search** view under **Investigate**. It distinguishes Search from **Transaction diagnostics**. | **Updated:** C8 retains **Search (formerly Transaction search)** and dates the Learn check specifically for that label. The date does not claim a new portal or telemetry test (`site/src/content/docs/challenges/c08-validate-the-pattern.md`). |
| OpenTelemetry distro | The [current Learn page](https://learn.microsoft.com/azure/azure-monitor/app/opentelemetry-enable) says new .NET, Node.js, and Python apps—or apps adopting OpenTelemetry for the first time—should use the **Microsoft OpenTelemetry Distro**. Existing users of the **Azure Monitor OpenTelemetry Distro** need take no action. Java guidance still uses the Azure Monitor distro. | C6 accurately retains the kit’s runtime-validated Azure Monitor distro and says adopting the Microsoft distro would require separate runtime revalidation. This is not a recommendation to switch the existing kit during the challenge. |
| Five redirected links | The 29-Oct site review recorded five link occurrences redirecting to other Learn pages. PR #210 reports canonical replacements and that 22 changed Learn references returned HTTP 200 on 30-Oct. Current source contains the updated Policy links and canonical SQL MI migration paths; the reviewed old path strings are no longer used in the site content. | **Previously addressed in #210.** This report did not rerun all five redirects or the full external-link check. |

C7 already states **Portal documentation checked on 2026-10-30** and distinguishes that source check from a live portal run (`site/src/content/docs/challenges/c07-migrate-and-go-live.mdx`). Its date and the Arc/MI-link guide's source-check date are unchanged. |

## Conclusion

The original claims were recorded in the T09 review and issue #198, then addressed in part by merged PR #210. Direct checks of current Microsoft Learn pages confirm the Upgrade Assistant deprecation, the `@upgrade` VS Code entry point, the Search label, and the conditional OpenTelemetry recommendation. The 2026-10-31 follow-up removes the embedded-dashboard claim and unverified **Execution** tab instructions, dates C8's Search source check, and adds the missing scoped prompt-review dates.

C7 already carries a documentation-check date. The owner accepted the earlier B07 evidence and partial 2026-10-31 observations and waived the remaining portal re-validation for #198, as recorded in the [issue evidence](https://github.com/jonathan-vella/apex-factory-hackathon/issues/198#issuecomment-6523722792). Do not present the partial check as a complete current portal verification. The Upgrade-toolchain retest remains deferred until next week; `versions.md` and the recorded runtime baseline are unchanged. No Azure operation or issue-status change was made by this documentation follow-up.
