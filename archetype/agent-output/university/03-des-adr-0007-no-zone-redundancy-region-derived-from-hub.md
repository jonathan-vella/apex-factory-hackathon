## 🔍 Context

> “The web app runs on a single P0v3 instance with no zone redundancy, and SQL MI General Purpose is a single instance with no zone redundancy. Both are single points of failure (owner-accepted).” (02-architecture-assessment.md)

Requirements set reliability as “Best-effort; no availability target (lab, redeploy from IaC)” for a training/demo platform with no production data. The assessment's region row reads “`swedencentral` (derived from the hub; `germanywestcentral` approved)”, and preflight requires the hub region to be one of the two.

## ✅ Decision

Do not enable zone redundancy on the web app or SQL MI, and take the region from the hub (`swedencentral`, with `germanywestcentral` approved as the alternate). Premium ACR and Premium Service Bus keep the zone redundancy they gain automatically in `swedencentral` at no extra cost; that is not an enabled option and is not removed.

## 🔄 Alternatives Considered

Arrows are qualitative: ↑ improves the pillar, → is neutral, ↓ weakens it.

| Option | Pros | Cons | WAF Impact |
| --- | --- | --- | --- |
| Single instance, no zone redundancy (selected) | In the priced Step 2 design; owner-accepted | Single points of failure for the web app and SQL MI | Reliability ↓, Cost Optimization ↑ |
| Zone-redundant web app and SQL MI | Better resilience to a zone failure | Not priced in Step 2; a zone-redundant SQL MI cannot be stopped, which would block the ADR-0008 schedule ([Microsoft Learn](https://learn.microsoft.com/azure/azure-sql/managed-instance/instance-stop-start-how-to)) | Reliability ↑, Cost not assessed |
| Multi-region | Not assessed | Not designed or priced | Not assessed |

## ⚖️ Consequences

### Positive

- Stays at about $1.81/hour against the brief's soft ~$1.83/hour. The brief sets no fixed monthly cap.
- The region follows the hub (the spoke is already vended there). `germanywestcentral` would cost about $0.10/month more (assessment).

### Negative

- A zone-local or region-local outage takes the web app and SQL MI down. There is no automatic failover or disaster-recovery replication.
- Recovery is best-effort and owner-initiated: redeploy from IaC. SQL MI keeps automated backups (local redundancy) with point-in-time restore.

### Neutral

- The design is accepted for a training/demo platform with no production data, not for a production service.

## 🏛️ WAF Pillar Analysis

| Pillar | Impact | Notes |
| --- | --- | --- |
| Security | → | No change in security posture is introduced by the region or zone decision. |
| Reliability | ↓ | Single points of failure with no availability target; best-effort, redeploy from IaC. |
| Performance | → | Not assessed. |
| Cost Optimization | ↑ | Priced in Step 2; no zone-redundant option was priced. |
| Operations | ↑ | Fewer components to manage; keeps the ADR-0008 schedule usable. |

## 🔒 Compliance Considerations

- The region is the hub's, which preflight requires to be `swedencentral` or `germanywestcentral`.
- Zone redundancy is revisited only if the platform stops being a training/demo lab or gains an availability target.

## 📝 Implementation Notes

- Take the region from the hub; record `germanywestcentral` as the approved alternate only.
- Keep single instances for the web app and SQL MI. Do not add zone redundancy without reopening Step 2.
- Treat this as an accepted lab trade-off, not a permanent exception.
