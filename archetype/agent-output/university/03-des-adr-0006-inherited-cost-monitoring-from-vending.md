## 🔍 Context

> “Cost monitoring: inherited from the landing zone. Vending (B08) already creates the subscription budget `budget-factory-workload` with an e-mail alert at 80%. The archetype creates no budget and no Action Group, and adds no deploy inputs (`cost_alert_emails = []`).” (01-requirements.md > Budget)

Requirements record `cost_monitoring_mode = deferred` with the exception rationale “inherited from landing zone” and a review date of 2027-01-03, reviewed sooner if B08's vending budget changes or the event date is set. The decision is whether the workload adds its own budget, Action Group and alerts or inherits the vended budget.

## ✅ Decision

Inherit the vended subscription budget and create no workload budget, Action Group or anomaly alert. This holds only for the current dev exception, which expires on 2027-01-03, or earlier if the B08 vending budget changes or an event date is set. The governance exception must be refreshed before deferred mode continues past that date.

## 🔄 Alternatives Considered

Arrows are qualitative: ↑ improves the pillar, → is neutral, ↓ weakens it.

| Option | Pros | Cons | WAF Impact |
| --- | --- | --- | --- |
| Inherit the vended budget (selected) | No new resources or inputs; the owner-approved no-input path | Only an 80% budget e-mail; no anomaly alert, no Action Group, no health-action notification | Cost Optimization ↑, Operations ↑ |
| Dedicated workload alerting (enforced default mode) | Anomaly alert and Action Group | Adds budget, Action Group and alert inputs the owner declined; `cost_alert_emails` is empty | Cost Optimization ↓, Operations ↓ |
| No monitoring | Simplest | Not an option: the vended 80% e-mail already exists | Not applicable |

## ⚖️ Consequences

### Positive

- Keeps the design aligned with the shared cost-monitoring baseline.
- Avoids creating unnecessary alerting resources in the workload subscription.

### Negative

- Cost visibility is limited to the vended 80% budget e-mail. There is no anomaly alert and no health-action notification; both gaps are accepted by the owner.
- Deferred mode expires on 2027-01-03 and needs a refreshed governance exception.

### Neutral

- This decision is about operational governance, not the app’s runtime behavior.

## 🏛️ WAF Pillar Analysis

| Pillar | Impact | Notes |
| --- | --- | --- |
| Security | → | The design does not broaden the security boundary by adding bespoke alerting resources. |
| Reliability | → | The inherited budget sends an e-mail at 80%. It is not an anomaly or health alert, and no health-action notification exists; those gaps are accepted. |
| Performance | → | No effect. |
| Cost Optimization | ↑ | No duplicate budget or alert resources. |
| Operations | ↑ | Nothing new to own; notifications go to the vending budget's contacts. |

## 🔒 Compliance Considerations

- The exception expires on 2027-01-03, or earlier if the B08 vending budget changes or an event date is set. Step 3.5 persists it in governance state; `cost_alert_emails = []` is not an implicit opt-out.

## 📝 Implementation Notes

- Create no budget, Action Group or anomaly alert. The archetype only checks the vended budget read-only before deployment (capability 17), which needs budget read access.
- If the exception expires or B08 changes, revisit this ADR before continuing.
