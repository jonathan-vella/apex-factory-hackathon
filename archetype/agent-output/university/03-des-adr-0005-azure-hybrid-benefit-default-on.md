## 🔍 Context

> “Azure Hybrid Benefit on SQL MI (owner assumption on licence eligibility). The licence-included alternative is shown in the cost estimate.” (02-architecture-assessment.md)

The Step 2 estimate prices SQL MI with Azure Hybrid Benefit (`BasePrice`) and brings the workload to $1,320.95/month (about $1.81/hour), 1.1% under the brief's soft ~$1.83/hour. The question is whether AHB or licence-included is the default.

## ✅ Decision

Keep Azure Hybrid Benefit on by default for SQL MI. Use licence-included only if licence eligibility is not confirmed.

## 🔄 Alternatives Considered

Arrows are qualitative: ↑ improves the pillar, → is neutral, ↓ weakens it. Prices are compute and licence from `02-cost-estimate-sqlmi-options.json`.

| Option | Pros | Cons | WAF Impact |
| --- | --- | --- | --- |
| AHB default (selected) | $488.92/month at 730 h; $174.61/month scheduled after C7 | Depends on the owner's licence-eligibility assumption | Cost ↑ |
| Licence-included by default | No eligibility dependency | $780.82/month at 730 h (+$291.90); $278.85/month scheduled after C7 | Cost ↓ |
| Mixed approach | Not assessed | Not priced | Not assessed |

## ⚖️ Consequences

### Positive

- Keeps the design aligned with the approved pricing and budget assumptions.
- Reduces the total cost of the SQL MI footprint without changing the workload architecture.

### Negative

- Requires a clear license-eligibility validation before deployment if the owner does not confirm the assumption.
- A future licensing exception would require a cost and deployment review.

### Neutral

- The decision does not change the database topology or runtime design.

## 🏛️ WAF Pillar Analysis

| Pillar | Impact | Notes |
| --- | --- | --- |
| Security | → | Licensing choice does not change the security architecture. |
| Reliability | → | The design remains unchanged from a platform reliability perspective. |
| Performance | → | SQL MI performance characteristics remain the same regardless of license model. |
| Cost | ↑ | The design is intentionally optimized to reduce monthly cost for the current supported architecture. |
| Operations | → | The selected model requires validation but does not change runtime operations. |

## 🔒 Compliance Considerations

- The decision should remain aligned to the owner-approved licensing assumption and not create hidden cost variance in the workload estimate.
- If AHB eligibility cannot be confirmed, the design must explicitly revert to the license-included scenario rather than silently assuming entitlement.

## 📝 Implementation Notes

- Keep the current AHB assumption in the pricing and SKU record unless a new owner decision or compliance rule changes it.
- Document the fallback to the license-included model as a controlled exception rather than as the default path.
- Treat the licensing decision as a cost-control assumption, not as a platform design change.
